# Riotランク戦試合データ：チャンピオン別コンボ・カウンターピック分析

## 要約

`raw/sources/riot-ranked-matches/` のMatch-v5データをキュー420に限定し、チャンピオンごとの味方コンボと同ロール対面候補を集計した。2026-09-15の実行では、13,120ファイル・19,107レコードを試合IDで統合し、重複6,000件、競合0件、不完全試合0件の13,107件の完全試合を対象にした。データは14.19〜16.18の48パッチを含む。

このページでいう「コンボ」は対象チャンピオンと同じチームに出場した味方チャンピオン、「カウンターピック候補」は対象と同じ正規化ロールで反対チームに出場したチャンピオンである。いずれも最終スコアから復元した記述統計で、実際のレーン対面や因果効果を保証しない。

## 主要な観測

- 全173チャンピオンentityを対象に、15試合以上の味方候補9,532行、同ロール対面候補2,264行を得た。
- レポート生成時の選定結果は394行（コンボ210、カウンター候補184）で、そのうち262行はn≥30、132行はn<30だった。n=15をレポート掲載下限、n=30を「十分性の目安」とした。
- entityの短い表示は、同じ `analysis.json` の候補全体から再選定し、各チャンピオンの最大2ロールについて、コンボを高勝率側から最大3件、カウンターピックを対象側の低勝率側から最大3件へ拡張した。今回のentity表示はコンボ561行、カウンター候補453行、計1,014行で、n≥30が699行、n<30が315行である。
- 小標本の極端な勝率を過大評価しないため、n≥30の候補が存在する場合はその集合から、コンボは95% Wilson区間の下限、対面は上限を優先する。掲載値は必ず実測の勝敗数と分母を併記する。
- entity表示の拡張は既存の `analysis.json` を使った同期であり、rawデータの再集計や新しい試合レポートの生成を伴わない。詳細レポートの全候補と、レポート生成時点の選定表は元の実行ディレクトリに保持する。
- 例として、カイ＝サ BOTTOMのコンボ候補はレオナ（91勝／154試合、59.1%）、同ロールの対面候補はルシアン（16勝／46試合、34.8%）だった。
- ヨネでは、MIDDLEのコンボ候補がジャーヴァンIV（24勝／33試合、72.7%）、TOPのコンボ候補がガリオ（29勝／42試合、69.0%）だった。これは関連するチャンピオン・ロール・パッチを調整した因果的な効果ではない。

## 解析方法

| 項目 | 条件 |
| --- | --- |
| 入力 | `raw/sources/riot-ranked-matches/` |
| キュー | `420` |
| 重複処理 | 試合ID単位で統合、`tier_mode=all` |
| 完全試合 | 10参加者、2チーム各5人、勝敗・試合時間が解決できる試合 |
| コンボ | 同一チーム内の対象チャンピオンと味方のペア |
| 対面 | `teamPosition`、`individualPosition`、`lane` から正規化した同ロールの相手 |
| レポート掲載下限 | n≥15 |
| サンプル十分性の目安 | n≥30 |
| 選定 | コンボはWilson下限の降順、対面はWilson上限の昇順。勝率・試合数をタイブレークに使用 |

対象側勝率は、対象チャンピオンが所属するチームの勝利数をその組み合わせの試合数で割った値である。コンボは同じペアを順不同に扱うが、各entityでは対象チャンピオンから見た勝率を記載する。対面は対象側の勝率が低い候補をカウンター候補として扱う。

## データ品質と限界

入力に競合する試合本体や不完全試合はなかった。一方、同じ試合が複数の収集経路に現れたため重複6,000件を試合IDで統合した。`tier_mode=all` では観測ランク帯を混合し、実際の試合時ランクとして扱っていない。

`teamPosition` 等は最終Match-v5スコアからのロール推定であり、実際にレーンで対面したか、途中でロール交換したかは分からない。勝率はプレイヤー、パッチ、構成、試合時間、先行状況、選択バイアスを調整していない。n<30の結果はentityへ掲載するが、探索的な参考値であり判断の根拠を弱く扱う。
