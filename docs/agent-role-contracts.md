# エージェント役割契約

この文書は、`llm-wiki` が蓄積したドメイン知識を、別のエージェントへ安全かつ短く渡すためのプロンプト契約である。ドメイン知識そのものは `wiki/` に置き、役割・権限・出力形式は呼び出し時に明示する。

## 使い分け

- ルートの `AGENTS.md` は、このVaultを維持する `llm-wiki-editor` の共通ポリシー（原典、索引、ログ、編集境界）を定義する。
- 参照だけを行うエージェントには、ルートの編集者ポリシーを「編集権限」として解釈させず、下記の `llm-wiki-reader` 契約を system/developer メッセージへ追加する。
- 役割契約をVault内に別の `AGENTS.md` として都度作らない。階層的なAGENTS探索で編集者ポリシーを意図せず上書きしたり、逆に参照専用の境界を見失ったりするためである。必要なら、呼び出し側の作業ディレクトリ（Vault外）にタスク固有の契約を置く。
- `AGENTS.md` に大量のチャンピオン・アイテム・試合統計を埋め込まない。変化する知識は `wiki/index.md` から辿らせ、`AGENTS.md` は安定した運用規則だけにする。

## 最小契約（system/developerメッセージへ貼り付ける）

```yaml
role_id: llm-wiki-reader
identity: "llm-wikiの参照専用エージェント。llm-wiki-editorではない"
authority: read-only
read_scope:
  - wiki/index.md
  - wiki/sources/**
  - wiki/concepts/**
  - wiki/syntheses/**
  - wiki/entities/**
  - raw/sources/**  # Wikiの主張を原典へ照合する必要がある場合だけ
write_scope: []
source_order: [wiki/index.md, 関連Wikiページ, 必要時のみraw/sources]
output_contract: "日本語。事実・推論・未解決を分離し、Wikiページと原典要約へリンクする"
prohibitions: [ファイル編集, 削除, 移動, リネーム, レポート生成, git操作, コミット]
```

最小契約の直後に、次の一文を明記する。

> あなたは `llm-wiki-reader` であり、`llm-wiki-editor` ではない。回答だけを返し、Vault内のファイルやGitを変更してはならない。

## 呼び出し手順

1. system/developerメッセージで最小契約とVaultの絶対パスを渡す。ユーザーの質問文だけで役割を推測させない。
2. エージェントには最初に `wiki/index.md` を読み、関連する `wiki/sources/`、`wiki/concepts/`、`wiki/syntheses/`、`wiki/entities/` だけを選ばせる。
3. 主張の検証が必要なときだけ `raw/sources/` を読む。`reports/` は派生成果物なので、原典要約を経由して引用する。
4. 回答では、(a) Wikiで確認できる事実、(b)エージェントの推論、(c)不足している原典・未解決事項を見出しまたはラベルで分ける。
5. 更新案が見つかっても直接編集せず、必要なら「編集者へ渡す提案」として対象ファイル、根拠、差分概要を返す。編集は明示的に `llm-wiki-editor` を起動した別タスクで行う。

## 実行時の強制境界

役割契約はエージェントに守るべき振る舞いを伝えるもので、単独ではOSやツールの権限を制限しない。readerを本当に参照専用にするには、呼び出し側でも次を設定する。

- readerの作業ディレクトリをVault外に置き、Vaultの絶対パスを参照先として渡す。これにより、Vaultルートの編集者向け `AGENTS.md` を作業ディレクトリの既定指示として誤って扱いにくくする。
- `wiki/`（必要なら検証用の `raw/sources/`）をread-onlyで公開し、`write_scope: []` と一致するようファイルシステムの書き込みを拒否する。
- `apply_patch`、シェル書き込み、削除・移動、レポート生成、Git操作などをreaderのツール許可リストから外す。契約の禁止語だけに依存しない。
- readerの終了後に、呼び出し側が変更ファイル一覧を検査する。更新が必要なら、readerの出力を入力にして、別の `llm-wiki-editor` タスクを明示的に起動する。

### 呼び出し側の短縮テンプレート

毎回の質問に長い運用規則を貼り直さず、次の固定契約と質問固有の参照候補だけを渡す。

```text
ROLE: llm-wiki-reader
IDENTITY: llm-wikiの参照専用エージェント。llm-wiki-editorではない。
VAULT: <Vaultの絶対パス>
READ: <VAULT>/wiki/index.md → 質問に必要なwikiページ → 必要時のみ<VAULT>/raw/sources
WRITE: なし。ファイル、レポート、Gitを変更しない。
OUTPUT: 日本語。事実／推論／未解決を分離し、参照したWikiページと原典要約へリンクする。
QUESTION: <ユーザーの質問>
```

`<質問固有の参照候補>` を後から追加する場合も、まず索引を読ませ、候補を最小集合に絞る。これが大量の全ページを毎回コンテキストへ投入しないための境界になる。

## 編集者との境界

| 項目 | `llm-wiki-reader` | `llm-wiki-editor` |
| --- | --- | --- |
| 目的 | 既存知識を根拠付きで回答へ利用 | 原典を取り込み、Wikiを更新・整合 |
| 書き込み | なし。回答本文のみ | `wiki/`、索引、ログを規則に従って更新 |
| `raw/` | 読み取りのみ。原典照合時に限定 | ユーザーが明示した追加以外は変更しない |
| `reports/` | 読み取り・評価の補助のみ | 生成時の条件、品質、原典追跡を記録 |
| 不確実性 | 断定せず、出典不足として返す | Wikiへ記録し、必要な原典を提案 |
| Git | 操作しない | ユーザーが依頼した場合だけ実行 |

## 役割を見失わせないためのチェック

- プロンプト内に `identity` と「`llm-wiki-editor`ではない」の両方を含める。
- `write_scope: []` と禁止操作を列挙し、「参照専用」という形容詞だけに依存しない。
- 回答の必須形式（日本語、Wikiリンク、原典要約リンク、事実・推論・未解決の分離）を契約へ含める。
- ルート `AGENTS.md` を読んだ結果、エージェントが編集者として振る舞おうとした場合は、reader契約を優先し、編集せずに提案で止める。
- 複数エージェントを同時に使う場合も、各エージェントへ同じ `role_id` を暗黙に共有せず、reader／editorを個別に渡す。
